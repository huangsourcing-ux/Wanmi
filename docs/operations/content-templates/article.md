# 文章内容模板

适用于指南、比较、解释和资讯。不要在模板中写具体业务结论；项目负责人应根据已核验来源持续补充。

## 后台字段填写

| 字段              | 填写要求                                                   |
| ----------------- | ---------------------------------------------------------- |
| `title`           | `【用户问题或主题】｜【必要限定】`；正文不要重复 H1。      |
| `slug`            | `【stable-lowercase-slug】`                                |
| `summary`         | `【用 1～2 句给出文章解决的问题、适用对象和关键限制】`     |
| `categories`      | `【选择 1 个主要分类；必要时增加少量次要分类】`            |
| `tags`            | `【选择能帮助检索的具体概念；不要创建同义标签】`           |
| `relatedTools`    | `【选择正文实际使用或解释的工具】`                         |
| `relatedTldPages` | `【选择正文直接讨论且已发布的 TLD 页面】`                  |
| `source`          | 按[统一来源格式](README.md#统一来源格式)填写，发布前必填。 |
| `meta.*`          | 按[统一 SEO 规范](README.md#统一-seo-规范)填写并确认。     |

## 正文模板

```text
【如为赞助内容，第一段显著写：赞助内容｜赞助方：【主体】｜合作关系：【说明】】

适用读者：【谁会遇到这个问题】
作者：【姓名/团队】
编辑：【姓名】
最后事实核验：【YYYY-MM-DD】

【导语：用一段话说明问题、为什么重要，以及本文不覆盖什么。】

## 先说结论

- 【可执行结论一】
- 【可执行结论二】
- 【关键限制或不确定性】

## 背景与适用范围

【解释必要概念、前提、数据时间范围和适用地区/用户。避免与主题无关的历史铺陈。】

## 操作步骤或判断方法

1. 【步骤/判断一：输入、动作和预期结果】
2. 【步骤/判断二：输入、动作和预期结果】
3. 【步骤/判断三：输入、动作和预期结果】

## 方案比较（不适用则删除）

- 【方案 A】：【适合谁、优势、限制】
- 【方案 B】：【适合谁、优势、限制】
- 【选择条件】：【如何根据事实选择】

## 风险、限制与常见误区

- 【不能从现有数据推出的结论】
- 【时效性、缓存、provider 或政策限制】
- 【安全、隐私、费用或操作风险】

## 下一步

【引导读者使用已关联工具或阅读已关联 TLD 页面；不要在正文手写可能变更的站内路径。】

## 来源与授权

- 【机构/作者】，《【标题】》，【URL】，访问日期：【YYYY-MM-DD】，用途：【事实/定义/数据】
- 【图片作者/机构】，【原始 URL 或授权编号】，获取日期：【YYYY-MM-DD】
- 授权/引用说明：【原创、合理引用、公开许可、转载授权或赞助关系】

## 修订记录

- 【YYYY-MM-DD】：【作者/编辑】｜【新增、修正或删除了什么】｜依据：【来源或原因】
```

## SEO 与来源检查

- `meta.title` 约 20～32 个中文字符，准确覆盖主要搜索意图；`meta.description` 约 70～120 个中文字符。
- OG 图片为已审核站内 Media，`alt`、来源和授权完整。
- canonical 默认留空；`noIndex` 默认关闭。任何例外都在审核备注中说明原因。
- `source` 与正文来源清单一致；转载有授权，赞助关系在首段可见。

## 提交审核前检查

- [ ] 所有占位符和不适用标题已清除。
- [ ] 作者、编辑、核验日期、来源和修订记录完整。
- [ ] 结论可由来源支持，价格/规则写明时间和限制。
- [ ] 相关工具、TLD、分类和标签真实相关，且没有依赖未发布页面完成核心说明。
- [ ] 已在私有预览检查标题层级、列表、链接、图片、移动端阅读和赞助标识。
