# 首批内容模板使用说明

本目录提供文章、专题、TLD 页面和帮助页四套可直接填写的 Payload 内容模板。模板只规定结构、字段和发布质量门槛，不包含具体业务内容。发布操作统一按[内容发布 Runbook](../content-publishing.md)执行。

## 模板目录

- [文章模板](article.md)：指南、比较、解释和资讯；首批主题可围绕域名选择与注册、DNS/WHOIS、SSL/建站。
- [专题模板](topic.md)：榜单、报告、系列内容和赞助栏目。
- [TLD 页面模板](tld-page.md)：后缀用途、规则、价格来源、工具和相关文章。
- [帮助页模板](help-page.md)：数据来源、术语、操作说明和故障处理。

## 统一字段口径

| Payload 字段                       | 系统要求                     | 发布口径                                                                                                                             |
| ---------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `title`                            | 保存必填                     | 准确描述页面主题；不要堆砌关键词或使用无法证实的承诺。页面会自动把它作为 H1，正文不要再写 H1。                                       |
| `slug`                             | 保存必填、同 Collection 唯一 | 使用稳定的小写 ASCII 单词和连字符；不要包含日期、查询参数、片段或将来可能频繁变化的信息。改址必须另建 301。                          |
| `summary`                          | 系统可选                     | 本模板规定发布前必填；用 1～2 句说明读者能获得什么，不复制标题。未填 SEO 描述时，它也是默认描述来源。                                |
| `content`                          | 保存必填                     | 只使用后台允许的段落、H2～H4、列表、引用、强调、行内代码、受控链接和站内 Media 图片。禁止粘贴 HTML、脚本、嵌入、内联样式或外链图片。 |
| `source`                           | 保存可选、发布必填           | 使用下方来源格式；它会直接显示在公开页。多个来源时填写最主要来源，并在正文“来源与授权”列全。                                         |
| `categories` / `tags`              | 仅文章、系统可选             | 使用已有且准确的分类/标签，避免创建同义词。只有包含已发布文章的分类/标签才公开。                                                     |
| `relatedTools`                     | 系统可选                     | 只选择正文确实解释或使用的工具；TLD 页面与其他内容均支持。                                                                           |
| `relatedTldPages`                  | 文章、专题、帮助页可选       | 只选择已发布且与正文直接相关的 TLD 页面；TLD 页的相关内容由反向关系自动生成。                                                        |
| `meta.*`                           | 系统可选                     | 按下方 SEO 规范逐项确认；模板规定发布前完成确认，即使决定留空。                                                                      |
| 工作流、计划时间、发布时间、修订人 | 系统自动                     | 不直接修改。使用页面顶部自定义工作流按钮，编辑身份由版本、`revisionBy` 和审计记录追踪。                                              |

“系统要求”描述 schema 或工作流的硬校验；“发布口径”是首批内容的运营质量门槛。二者都必须满足。

## 统一 SEO 规范

- `meta.title`：建议 20～32 个中文字符，先写主题和用户意图，再写必要限定；不重复品牌、不堆关键词。留空会使用 `title`。
- `meta.description`：建议 70～120 个中文字符，概括答案、适用范围和关键限制；不写无法验证的“最好”“保证”等承诺。留空会使用 `summary`。
- `meta.image`：优先 1200×630；格式只能是 JPEG、PNG、WebP 或 AVIF，建议小于 500 KB。Media 必须填写准确 `alt`、来源，确认授权后勾选 `reviewed`。
- `meta.canonical`：默认留空，让系统按内容类型和 `slug` 生成。只有确认当前页是重复页时才填写 Wanmi 主域内、不含查询参数或片段的干净路径/同源 URL。canonical 指向别页时，当前页不会进入 sitemap。
- `meta.noIndex`：计划公开收录时保持关闭。只有页面虽需公开访问但明确不应被搜索引擎收录时开启；开启后页面仍可访问，但会输出 `noindex` 并从 sitemap 排除。草稿、待审核、下线和归档无需靠它保密。

## 统一来源格式

`source` 只放纯文本，使用以下一种格式；将 `【】` 内占位内容全部替换：

```text
原创｜作者：【姓名/团队】｜编辑：【姓名】｜事实核验：【YYYY-MM-DD】
引用整理｜主要来源：【机构/作者】《【标题】》｜URL：【https://...】｜访问：【YYYY-MM-DD】｜依据：【合理引用/公开许可】
转载｜原作者/机构：【名称】｜原文：《【标题】》【https://...】｜授权：【授权方式或编号】｜授权日期：【YYYY-MM-DD】
赞助内容｜赞助方：【主体名称】｜作者/编辑：【姓名/团队】｜审核：【YYYY-MM-DD】
```

- 引用整理：正文“来源与授权”列出全部关键来源、URL、访问日期，以及哪些结论来自哪个来源；只引用必要范围。
- 转载：没有可追溯授权依据不得提交审核；保留原作者、原文地址和授权记录。
- 赞助内容：正文开头必须显著写明“赞助内容”、赞助方和合作关系；赞助不能隐藏，也不能伪装成工具结果或自然排序。
- 图片：Media 的 `source` 填“原创/机构或作者/授权编号/原始 URL/获取日期”；无法确认权利或内容准确性时不得勾选 `reviewed`，不得发布。

## 统一填写规则

1. 复制对应模板的“正文模板”到富文本编辑器，替换所有 `【占位符】`。
2. 删除不适用的可选段落，不保留空标题、占位符或示例提示。
3. 外部链接只链接权威原始来源；不要使用协议相对地址、短链或带敏感查询参数的 URL。
4. 作者和编辑没有独立字段，必须在正文署名/修订记录和 `source` 中写明；后台版本和审计只负责追踪实际操作者。
5. 事实、价格、规则和日期必须标注适用范围与核验日期；动态价格不得写成长期有效承诺。
