# D9-B-1 钱包账本安全与正确性判定变异对照表

一致性任务以及迁移约束。每次只应用一个删除或短路变异，运行表中唯一指定的行为用例，并在
`finally` 中恢复原文件。只有非零退出且包含行为断言失败的运行才计为杀死；编译、装载、变异定位
失败均不计入。源码文本断言只用于补充确认没有 `payload.update({ where })`，不计为行为杀死证据。

## 3. 迁移约束与 down 清理（38/38）

迁移验证器在独立临时数据库中提取并执行 D9-B-1 `up` SQL，实际提交非法 UPDATE/INSERT；CHECK、
unique 或 FK 删除后，必须出现“accepted an invalid write”。随后执行 `down` 并验证三表与 workflow enum
值均清理；down 删除已排队 workflow 的语句与枚举缩窄分为两个数据库调用，保证前一语句的效果在
缩窄前可见。两个曾经存在但逻辑冗余的条件没有纳入结果：`posted >= 0` 已被
`held >= 0 AND held <= posted` 蕴含；`held <= MAX` 已被 `posted <= MAX AND held <= posted` 蕴含，最终
迁移已删除二者，避免无法单独承重的伪判定点。

## 4. 恢复后基线

全部变异恢复后，D9-B-1 单元/集成聚焦套件为 43/43，D9-A 账号注销兼容回归为 54/54；独立迁移行为
验证为 26 个 CHECK 谓词、4 个 unique index、6 个 FK 和 down 清理全部通过。账号注销余额门禁复用同一
追加式账本推导服务，账户缺失返回无余额，查询异常或账本不一致均失败关闭。本地 wallet fixture 最终计数为
`walletAccounts:walletTransactions:walletEntries = 0:0:0`。完整 `make check`、精确 commit CI 和生产写入
声明记录在开发日志与 PR 报告；变异期间只使用本地 PostgreSQL 与临时数据库，没有部署或生产写入。
