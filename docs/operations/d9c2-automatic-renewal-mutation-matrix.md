关键数据来源替换分别覆盖：最新 revision 改读最旧 revision；mandate 上限改读当前报价；存在记录替代
`eventType`、`revokedAt` 或 `validUntil`；资产 owner 替代 mandate customer；本地 expiry 替代上游 expiry；
订单旧 mandate/金额/规则快照替代履约时最新事实。fixture 对每一项分别构造“其他字段仍看似有效”的反相关
事实。`execute-mandate-required` 变异只删除统一有效性服务中的真正授权谓词；入口曾有的重复早退已删除，
避免把等价防线错误计作两个判定点。

## 4. 指定验收用例

- 无、已撤销、已过期 mandate：参数化用例三行分别运行，且 `revoked` fixture 将 `revokedAt` 置空以证明
  `eventType` 来源独立。
- 上限：3,500 分报价对 3,499 分 mandate 不 hold 并发价格提醒；对 3,500 分 mandate 允许。
- 不足余额与上限：available/held/posted、目标 account 的 hold 计数、目标 asset/cycle 的提醒计数均直接断言。
- 确定性：同一批乱序输入执行两次，直接断言两次处理序列均为 expiry asc、numeric asset id asc。
- 入队后关闭：queue-time、D6 preflight 前、paid→fulfilling 前三处分别重新读取最新 mandate；撤销或替换均
  release 完整 hold 并追加 skip，不调用上游 renew。
- 域名状态：本地 expired、上游 expiry 不一致、EPP redemption、registry restricted 分别失败关闭。
- step-up 分离：无人值守路径对 step-up 模块 spy 为零调用；授权/撤销路径必须消费专用一次性 grant。
- 并发：同域并发触发只产生 1 个 hold、1 个 capture、1 个 provider renew；撤销/hold 两种锁顺序均确定且
  available 不为负。
