# D9-A A7 安全与正确性判定点变异矩阵

日期：2026-08-16

范围：仅 D9-A A7 同意与个人信息

最终结果：JS/接口/权限判定 115/115，SQL 谓词 12/12，合计 127/127 均由指定行为断言杀死。

## 执行口径

- `apps/web/scripts/mutate-a7-security-decisions.mjs` 对每个 JS guard、早退分支、权限判断和调用插入点单独删除或短路，逐项只运行能观察该行为的指定测试；只有输出 `AssertionError` 才计为 `KILLED_BY_BEHAVIOR`。
- `apps/web/scripts/mutate-a7-sql-predicates.mjs` 对本切片两个并发敏感写路径和同事务 no-op 新鲜度读取中的 12 个 SQL 谓词逐一删除并实跑。
- 每次变异都在 `finally` 恢复原文件；最终基线测试与完整门禁在恢复后的源码上运行。
- 源码文本断言只辅助定位插入点，不作为杀死变异的唯一证据。
- 初轮发现的冗余判断没有伪装成“已覆盖”：一个被 `Number.isSafeInteger` 完全支配的 `typeof` 检查被删除；migration down 中被 PostgreSQL enum 原生转换失败完全支配的显式预检也被删除。最终矩阵只保留会改变可观察行为的判定点。

## 并发写入证据

| 写入                               | N 路 | 成功数 | 失败数 | 行为用例                                                                                          |
| ---------------------------------- | ---: | -----: | -----: | ------------------------------------------------------------------------------------------------- |
| 可选同意状态 CAS 与追加记录        |    8 |      1 |      7 | allows exactly one of 8 concurrent consent writes                                                 |
| 历史账号资料补全与两条真实条款证据 |    8 |      1 |      7 | allows exactly one of 8 legacy completions and records real evidence without rewriting provenance |

两条路径均在 Payload transaction 内使用单条 `UPDATE ... WHERE ... RETURNING` claim，并把后续
`consentRecords` 与审计追加写入同一 `req`；没有使用 `payload.update({ where })`。

## A3/A4 复用边界

A7 新增的资料补全与同意选择不改变账户状态，因此没有新增或绕过状态迁移。账户删除仍沿用 A3
`transitionCustomerAccount`，并在既有高风险入口沿用 A4 `account_deletion` step-up 与
`assertIdentityRiskCooldownInactive`；冷静期内失败关闭。自动续费同意记录仅表达文档同意，不替代
D9-C 独立 `renewalMandate`。A5/A6 未修改。
